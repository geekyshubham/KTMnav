# KTMnav native Android override

Applies to Ride, Garage, Apps and Settings. The verified database match was Minimalism & Swiss Style for navigation utility dashboard; use its functional hierarchy and spacing. Landing-page recommendations do not apply to the native application.

Product decisions: charcoal instrument surfaces, KTM orange, optional Husqvarna blue and daylight theme. Use licensed bundled Chakra Petch for headings/numerals, Android sans for body; no network fonts.

Dark tokens: background #101214, surface #191D20, raised #22272B, text #F2F4F5, muted #AAB5BC, boundary #71808A, accent #FF974F.
Daylight: background #F4F5F6, surface #FFFFFF, raised #E8ECEF, text #171B1E, muted #4D5B65, boundary #75848E, accent #AD4300. Husqvarna accent #8AB4F8 on dark surfaces.

Use 4/8dp spacing, 24dp phone gutters / 64dp tablet gutters; 48dp minimum touch targets, native switches and dialogs. Four bottom navigation destinations. Respect system bars/insets and system text scale. No continuous or decorative motion. Ripple feedback must keep layout stable. SVG-equivalent Canvas paths for icons; decorative icons hidden from accessibility.

Connection state is observed backend state only. Explicitly labeled dashboard preview cannot affect bridge state or send packets. Empty, permission-denied, unavailable-Bluetooth and scan-failure states have visible guidance.

## Gen 3 dashboard and setup refinement

Use grouped status, vehicle-information and telemetry cards with a visible label above each received value. Keep the unavailable and empty states readable and explain how values become available. Dashboard sending uses a disabled native button while disconnected. Refresh is explicit; data never animates into invented readings. Support controls stay in Settings, with pairing guidance in Garage and the compatibility help dialog.

The final UI review used the skill's verified Mobile Touch Target Size and All-platform Empty States matches. Android touch controls use at least 48dp. Theme-token text contrast was calculated independently; dark secondary text exceeds 7:1 and daylight secondary text exceeds 5.8:1 on the defined surfaces. Screenshot verification and its limits are recorded in docs/verification-gen3.

Incoming real guidance and explicit dashboard preview take priority over introductory setup copy. The phone-only button lab uses native 52dp controls, a persistent simulation label and a local preview selection; no lab event is routed to the motorcycle transport. Cruise-control capability is described as unsupported by the recovered interface.

## Version 1.2 control configuration

Handlebar mappings use a dedicated Settings dialog with a master execution switch, four saved action selectors, Android permission status, explicit screen-control disclosure, and a confirmable default reset. Saved assignments remain editable while execution is off. Native single-choice rows expose selection state; action buttons use at least 52dp targets. BACK follows the chosen action and does not trigger an extra legacy shortcut. Included features links directly to source settings and Garage, with no purchase UI. The relevant skill match is Mobile Back Button; permission disclosure uses native Android behavior and the skill's general accessible-form guidance because the focused permission search did not return a matching database rule.

## Version 1.4 refresh

Supersedes the 1.0–1.3 token values above where they differ. Contrast for every pair is recomputed by `scripts/check_design_tokens.py` into `docs/verification-1.4/design-token-contrast.json`.

Brand: KTM orange `#FF6600` is the primary fill in KTM dark and Daylight (primary buttons, selected navigation pill, launcher background). Anything placed on an orange fill uses `#101214` (6.39:1). Dark theme orange text/icons on surfaces stay `#FF6600` (5.78:1 on `#191D20`, 5.13:1 on raised). Daylight: orange icons `#E65C00` (3.56:1 on white, 3.22:1 on the `#FFF1E8` icon tile), orange text `#C24E00` (4.79:1 on white; never used on the `#F4F5F6` page background, where links use the text token). Husqvarna keeps `#8AB4F8` with `#101214` labels (8.91:1). New tokens: `tile` (icon tile; dark `#22272B`, daylight `#FFF1E8`), `divider` (decorative; `#2A3035` / `#DDE2E6`), `success` (connected dot / Active chip; `#7DD99B` / `#1E7B3A`). Theme `colorAccent`, `colorControlActivated` and a dedicated `alertDialogTheme` (surface background, 24dp radius, sentence-case buttons) replace every old orange (`#FF974F`, `#AD4300`, `#FF8A3D`) in switches, sliders, progress, dialogs and the Canvas turn arrow.

Layout: no marketing headers. Compact top bar = tab title (24sp Chakra Petch, accessibility heading) + connection chip (dot + text such as “Connected · Duke 390”, “Not connected”, “No motorcycle”; chip content description “Connection: …”, polite live region, so state never relies on colour). Spacing 4/8/12/16/24; 16dp phone gutters, content centred at max 720dp on tablets/landscape; cards 16dp radius, tiles/groups 12dp, buttons 24dp pill at 48dp min height. Primary = orange fill; secondary = outlined (1dp `line`, 4.17:1 / 3.85:1); tertiary = text button with icon. Ripples only, no elevation or size change on press. Bottom navigation uses Material Symbols icons with a 56×32dp selected pill; at ≥1.5 font scale it becomes a 2×2 icon+label grid.

Icons: Material Symbols Rounded, weight 400 (Apache-2.0, `@material-symbols/svg-400@0.23.0`), converted to 24dp VectorDrawables `res/drawable/ic_*.xml`, tinted by token at runtime. Icons beside visible text are `importantForAccessibility=no`. Third-party app icons come from `PackageManager.getApplicationIcon()` when the app is installed; since 1.5 a missing app shows KTMnav's own bundled icon for it (`ic_app_*`, a rounded tile in the app's dominant colour with a simple original glyph, drawn at 72 % opacity) instead of a monogram. Launcher: adaptive icon (`#FF6600` background, `#101214` navigation-arrow mark inside the 66dp safe zone, monochrome layer); no manufacturer logo or wordmark.

## Version 1.5 additions

Motorcycles: eight tintable side-view silhouettes (`ic_bike_naked`, `adventure`, `sport`, `enduro`, `supermoto`, `touring`, `scrambler`, `cafe`; 48-unit viewport, accent-tinted on the icon tile) replace the generic two-wheeler glyph in Garage and on the Ride header. The style follows the rider's model choice (Garage → bike → Motorcycle model, catalogue grouped by brand plus a Styles group) or a guess from the dashboard name; the generic glyph stays for unknown names.

Navigate card (Ride tab, idle state): one text field (search glyph, IME action Go, 52dp), an outlined app button carrying the app icon plus a primary Go pill, a horizontally scrolling row of favourite chips (Home, Work, star) with an outlined "Add favourite" chip, and up to five recent rows (48dp, history glyph) with a Clear text button. Long-press opens the edit/remove menus. The active-guidance panel adds an "Open <app>" text button. Settings gains a Navigation group (navigation app, two-wheeler routes switch, favourite places, clear recents). Rides gains a "Planned routes" group with an outlined "Import GPX route" button and a route sheet with the trace, three readings and a primary "Navigate this route" pill.

Patterns: grouped settings list (section header 13sp muted; 40dp icon tile + 16sp title + one 13sp summary + switch or chevron; whole row is the ≥56dp target; switch rows expose role Switch + checked state + hint). Setup checklist shows only unmet items (nearby devices, Bluetooth on, notification access, post notifications, battery exemption via `isIgnoringBatteryOptimizations`, saved motorcycle), re-evaluated in `onResume`; hidden entirely when complete; the Ride copy can be dismissed until a new item appears. Feature sheets show a compact “· Ready” row instead of request buttons once a permission is granted; long explanations moved to the permission disclosure dialogs or (i) links.

Verified ui-ux-pro-max matches applied (2.15.0 database): ux “Empty States” (All) — idle guidance panel, empty Garage, no-rides state each with one action; ux “Color Only” (All) — status chip text + dot, Active chip with check icon; ux “Color Contrast” / “Contrast Readability” (All) and app-interface “Light/Dark Contrast” — per-theme semantic tokens tested in all three themes; ux “Touch Target Size” (Mobile) — 48dp minimum, 56dp rows; app-interface “Icon Button Labels” and “Role & Traits” — content descriptions on icon-only close button, nav tabs as buttons with selected state, rows as Button/Switch; icons “icon-context-accessibility” — decorative icons hidden; ux “Loading Indicators” (All) — scan progress keeps layout and announces status; ux “User Freedom” (Onboarding) — setup on Ride can be hidden; ux “Active State” (Navigation) — selected tab pill; app-interface “Preserve Screen State” — scroll position kept on re-render. Searches for “settings list grouping”, “settings menu”, “section list grouped”, “app icon row” and “permission request” returned no database match; the grouped-list and permission-row patterns follow native Android Settings conventions as a labelled fallback.
